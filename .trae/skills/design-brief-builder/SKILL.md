# Design Brief Builder

## 任务目标

本 Skill 用于：将用户模糊的视觉偏好转化为量化的设计规范文档（Design Brief），让后续的设计和开发有统一的视觉标准。

触发条件：
- 用户描述视觉偏好（如"深色主题、极简风格"）
- 用户需要定义产品的设计风格
- 用户提到"UI"、"视觉"、"配色"、"主题"等关键词
- Product Spec 完成后，进入设计阶段时

## 核心原则

### 禁写令

**Do NOT generate any UI code, CSS, or style-related implementation until the user has approved the design brief.**

视觉方向不明确时，AI 从预训练数据拼凑的默认样式大概率不符合用户期望。

### 反模式防御

以下借口一律无效：

- ❌ "我先随便写个样式，后面再改" → 后面改的成本是现在的 3 倍
- ❌ "设计风格可以边做边调" → 边做边调 = 风格不一致、反复返工
- ❌ "深色主题就是黑底白字" → 深色主题有数十种变体，必须量化

## 执行流程

### 步骤1：视觉偏好收集（一次一问）

**追问维度**（按顺序）：

1. **整体调性**：你希望产品给人什么感觉？（专业/活泼/温馨/科技感/极简）
2. **配色方案**：
   - 主色调偏好（冷色/暖色/中性色/具体颜色）
   - 亮色还是暗色主题？
   - 有无品牌色要求？
3. **点缀色**：强调色/链接色/按钮色性格（激进/保守/自然）
4. **字体风格**：
   - 标题字体（衬线/无衬线/手写）
   - 正文字体（易读优先/个性优先）
   - 字号层级（大标题/小标题/正文/辅助文字）
5. **布局风格**：
   - 页面布局（居中/全宽/分栏）
   - 卡片风格（圆角/直角/阴影）
   - 间距密度（宽松/适中/紧凑）
6. **交互元素风格**：
   - 按钮样式（实心/描边/幽灵/渐变）
   - 输入框样式（下划线/边框/填充）
   - 列表/表格风格
7. **动效级别**：
   - 无动效（纯静态）
   - 微妙动效（hover 变化、过渡动画）
   - 丰富动效（页面切换动画、加载动画）

**提问规则**：
- 一次只问一个问题
- 可以展示 2-3 个参考风格让用户选择
- 用户回答模糊时，追问具体细节

### 步骤2：量化输出

收集完信息后，生成量化的 Design Brief 文档。

### 步骤3：用户确认

展示 Design Brief，等待用户确认或修改。

### 步骤4：保存文档

用户确认后，保存到 `docs/design/YYYY-MM-DD-<topic>-design-brief.md`。

## Design Brief 文档模板

```markdown
# Design Brief: [产品名称]

## 1. 整体调性
- 关键词：[如：专业、极简、科技感]
- 参考案例：[如有参考产品或网站]

## 2. 配色方案
### 2.1 主色
- 色值：[#XXXXXX]
- 用途：[如：背景、导航栏]

### 2.2 辅色
- 色值：[#XXXXXX]
- 用途：[如：卡片背景、分割线]

### 2.3 强调色
- 色值：[#XXXXXX]
- 用途：[如：按钮、链接、高亮]

### 2.4 文字色
- 主文字：[#XXXXXX]
- 辅助文字：[#XXXXXX]
- 禁用文字：[#XXXXXX]

## 3. 字体规范
- 标题字体：[字体族、字号、字重]
- 正文字体：[字体族、字号、行高]
- 代码字体：[字体族、字号]

## 4. 布局规范
- 页面宽度：[如：最大 1200px 居中]
- 栅格系统：[如：12 列]
- 间距系统：[如：4px 为基础单位，4/8/16/24/32]

## 5. 组件风格
### 5.1 按钮
- 样式：[实心/描边/幽灵]
- 圆角：[0/4/8/全圆角]
- 阴影：[有/无]

### 5.2 卡片
- 圆角：[0/4/8/12/16]
- 阴影：[有/无，阴影值]
- 边框：[有/无]

### 5.3 输入框
- 样式：[下划线/边框/填充]
- 圆角：[值]
- 聚焦状态：[边框变色/阴影]

## 6. 动效规范
- 级别：[无/微妙/丰富]
- 过渡时长：[如：200ms]
- 缓动函数：[如：ease-in-out]
```

## 输出格式

- 格式：Markdown
- 保存路径：`docs/design/YYYY-MM-DD-<topic>-design-brief.md`

## 错误处理

### 常见错误及解决方案

1. **用户说"随便，你定就好"**
   - 处理：提供 3 种预设风格（现代极简/科技感/温馨），让用户选
   - 记录："用户无明确偏好，AI 代为决策"

2. **用户需求与设计规范冲突**
   - 处理：指出冲突点，给出专业建议
   - 最终尊重用户选择

3. **视觉需求过于庞大**
   - 处理：先定义核心页面（首页、核心功能页）的规范
   - 其他页面后续补充

## 使用示例

### 输入示例

用户：我想要深色主题，极简风格

### 交互过程

AI：好的！让我细化一下深色主题的具体方向。你希望深色主题是：
- 纯黑底（#000000）：对比度极高，适合内容型产品
- 深灰底（#1a1a2e）：柔和一些，适合工具型产品
- 蓝黑底（#0d1117）：偏冷色调，类似 GitHub 的风格

你更倾向哪种感觉？

[继续追问点缀色、字体、组件风格...]
