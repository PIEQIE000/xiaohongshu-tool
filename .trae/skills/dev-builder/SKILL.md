# Dev Builder

## 任务目标

本 Skill 用于：按照 Dev Plan 中的 Task 清单逐条实现代码，每个 Task 完成后进行编译验证和测试，确保代码质量。

触发条件：
- 用户说"开始开发"、"按计划实现"、"开始编码"
- Dev Plan 确认后
- 用户说"继续开发"、"做下一个 Task"
- 用户提到"实现"、"编码"等关键词

## 核心原则

### 范围纪律

**Do NOT refactor adjacent systems. Do NOT delete code you don't fully understand.**

每次变更范围尽量控制在当前 Task 定义的范围内，不要借机重构不相关的代码。

### TDD 强制流程

必须遵循 RED-GREEN-REFACTOR 循环：

1. **RED（红）**：先写一个会失败的测试，证明测试本身是有效的
2. **GREEN（绿）**：写最少的代码让测试通过
3. **REFACTOR（重构）**：在测试通过的前提下重构代码

**禁止以下行为**：
- ❌ 先写代码后写测试
- ❌ 说"我已经手动测试了"跳过 TDD
- ❌ 说"这个情况不一样，不需要测试"
- ❌ 跳过 RED 阶段直接进入 GREEN

### 证据驱动完成

Task 完成的标志不是"代码写完了"，而是：

- ✅ 测试通过（单元测试/集成测试）
- ✅ 编译/构建无报错
- ✅ 功能验证符合验收标准

## 执行流程

### 步骤1：读取当前 Task

从 `docs/plans/` 目录下最新的 Dev Plan 中读取当前 Task 的定义：

- Task ID 和描述
- 涉及文件（新建/修改）
- 验收标准
- 依赖信息

### 步骤2：TDD - RED 阶段

编写会失败的测试用例：

1. 根据 Task 的验收标准，编写测试
2. **运行测试，确认它失败了**（看到红色）
3. 如果测试意外通过了，说明测试无效，需要重写

### 步骤3：TDD - GREEN 阶段

编写最少的代码让测试通过：

1. 只实现让当前测试通过所需的最小代码量
2. **不要提前实现**后续 Task 的功能
3. **运行测试，确认通过**（看到绿色）

### 步骤4：TDD - REFACTOR 阶段

在测试通过的前提下重构：

1. 优化代码结构、命名、重复代码
2. 每次重构后**重新运行测试，确认仍然通过**

### 步骤5：编译验证

运行项目的编译/构建命令，确保：
- 无编译错误
- 无警告（或已知且可接受的警告）

### 步骤6：功能验证

根据 Task 的验收标准，验证功能是否符合预期。

### 步骤7：标记完成

标记当前 Task 为已完成，进入下一个 Task。

### 步骤8：Context 隔离

**关键原则**：每个 Task 使用独立的上下文。

- 不继承上一个 Task 的上下文
- 只读取当前 Task 的定义和验收标准
- 如果项目结构或依赖信息不明确，重新读取 AGENTS.md

## 错误处理

### 常见错误及解决方案

1. **测试一直失败**
   - 处理：检查测试逻辑是否正确
   - 如果超过 3 次尝试，暂停并分析问题

2. **编译报错**
   - 处理：逐条分析错误信息
   - 一次只修一个问题，不要同时改多处
   - 修完重新编译，确认问题解决

3. **发现 Task 定义不完整**
   - 处理：暂停当前 Task
   - 回退到 dev-planner，要求更新 Dev Plan
   - 不要自己脑补缺失的规格

4. **发现 Spec 与实际实现冲突**
   - 处理：暂停，向用户确认
   - 不要擅自修改 Spec

## 使用示例

### 输入示例

用户：Dev Plan 确认了，开始实现

### 执行过程

AI：好的，开始执行 Dev Plan。

**当前 Task: T001 - 初始化项目结构**
- 涉及文件：package.json, tsconfig.json, src/index.ts
- 验收标准：项目可运行，输出 "Hello World"

1. 创建测试文件：tests/init.test.ts
2. 编写测试（预期项目可运行）
3. 运行测试 → 失败（符合预期，项目还没初始化）
4. 创建项目文件...
5. 运行测试 → 通过 ✅
6. 运行构建 → 无错误 ✅
7. **T001 完成**

下一个 Task: T002...

## 注意事项

- 每个 Task 完成后，自动记录进度到 Dev Plan
- 如果遇到阻塞，不要硬磕，标记为 BLOCKED 并向用户报告
- 同一个 bug 反复修了多次还没好，停下来重新审视问题本身
