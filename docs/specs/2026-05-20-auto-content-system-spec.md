# Product Spec: V2 自动化内容闭环系统

> **前置说明**：本文档是 [Phase 1-8 MVP Spec](./2026-05-19-xiaohongshu-content-tool-spec.md) 的迭代升级，描述从「手动工具」到「半自动/全自动内容工厂」的新增需求。所有「已有」标记的功能不需要重新实现，仅需扩展或集成。

---

## 1. 产品升级概述

### 1.1 从 MVP 到 V2 的核心变化

| 维度 | MVP（已实现） | V2（本 Spec） |
|------|-------------|--------------|
| 素材管理 | 上传/裁剪/浏览 | **分类素材库** + 使用追踪 + 疲劳检测 |
| 内容生产 | 手动选模板 → 点生成 | **自动化批量生成**，定时触发，多种内容类型自动拼装 |
| 发布 | 手动排期 → 手动复制 | **自动排期** + 生成待发布内容草稿 |
| 数据 | 手动录入总数据 | **按内容维度录入** + 自动分析 + 排名 |
| 策略 | 无 | **数据驱动**的内容配比调整 + 选题挖掘 + 素材缺口分析 |
| 用户交互 | 人在工具里操作 | **任务派发**：系统告诉用户缺什么素材、该拍什么 |

### 1.2 系统闭环

```
素材库(拍照入库) → 自动内容生成 → 排期发布 → 数据回收 → 策略分析 → 任务派发 → 素材库(按指令拍照)
```

### 1.3 用户画像确认（已在本对话中明确）

- 铝单板源头厂家，多在工厂/喷涂厂
- **不出镜**，视频用 AI 配音
- **以图文为主**，视频为辅
- 常用电脑，会 AI 出图
- 工作方式：定期去工厂批量拍照存库，系统自动产出内容

## 2. 新增模块需求

### 2.1 素材库 V2（Material Library Upgrade）

**对标已有**：`src/app/materials/page.tsx` + Asset 模型

#### 2.1.1 分类体系

素材按固定分类管理，类型用枚举值：

| 类型值 | 中文名 | 说明 |
|--------|--------|------|
| `production_line` | 生产线 | 开料、折边、焊接、打磨 |
| `spray_line` | 喷涂线 | 挂料、喷涂、烘烤、出料 |
| `raw_material` | 原材料 | 铝卷、铝板堆 |
| `finished_product` | 成品 | 不同颜色/造型的成品板 |
| `packing_shipping` | 打包发货 | 木架打包、装车、货车 |
| `detail_closeup` | 细节特写 | 游标卡尺测厚度、表面质感 |
| `color_swatch` | 色板 | 各种颜色的实物色板 |
| `ai_render` | AI 效果图 | 电脑 AI 生成的效果图 |

#### 2.1.2 素材使用追踪

每个素材记录：
- `usageCount`：使用次数
- `lastUsedAt`：最后使用时间

#### 2.1.3 素材疲劳检测

规则：同一素材使用超过 N 次（默认 3 次），标记为「疲劳」，自动生成时跳过该素材。

用户可在素材详情页手动重置或手动标记疲劳。

#### 2.1.4 素材覆盖率分析

页面新增「素材覆盖看板」：

- 按分类统计素材数量
- 低覆盖分类高亮提示（少于 5 张标黄，0 张标红）
- 导出覆盖报告

#### 2.1.5 验收标准

- [ ] 素材上传时必选分类类型
- [ ] 素材列表支持按分类筛选
- [ ] 素材卡片显示使用次数和最后使用时间
- [ ] 疲劳素材在生成时自动排除（可配置阈值）
- [ ] 覆盖率看板显示各分类素材数量和状态

### 2.2 任务调度中心（Task Dispatch）【全新模块】

#### 2.2.1 功能描述

系统根据素材库覆盖率和内容排期需求，自动生成「拍摄任务」，推送给用户。

用户按任务清单去工厂拍照，完成后标记任务完成。

#### 2.2.2 任务数据结构

```
MaterialTask:
  id: string (UUID)
  title: string (任务名称，如"补拍喷涂线挂料环节 5 张")
  description: string (详细说明)
  requiredTypes: string (需要补充的素材类型，逗号分隔)
  requiredCount: int (需要几张)
  status: "pending" | "done"
  dueDate: string? (截止日期)
  createdAt: DateTime
  completedAt: DateTime?
```

#### 2.2.3 任务生成规则

触发方式：
1. **手动触发**：用户在素材库点击「生成拍摄任务」
2. **自动触发**：每次素材库变更后，检测覆盖率缺口

生成逻辑：
- 遍历素材分类，找出 `count < 最低阈值(5)` 的分类
- 为每个缺口分类生成一条任务
- 已有未完成的同类任务时不重复生成

#### 2.2.4 任务列表页面

新增侧栏菜单项「拍摄任务」。

功能：
- 显示所有任务，按状态分栏（待完成/已完成）
- 支持手动创建/编辑/删除任务
- 完成任务后可跳转到素材上传页
- 显示任务统计：待完成 N 项

#### 2.2.5 验收标准

- [ ] 素材覆盖率看板可一键生成拍摄任务
- [ ] 任务列表支持按状态筛选
- [ ] 完成任务后可一键跳转素材上传
- [ ] 已有同类未完成任务时不重复生成

### 2.3 内容自动生成引擎（Auto Generation Engine）【核心模块】

**对标已有**：`src/app/content/page.tsx`（手动生成模式保留不变，新增自动化模式）

#### 2.3.1 内容类型定义

支持 4 种内容类型，每种有固定的配图逻辑和文案生成逻辑：

| 内容类型 | type 值 | 素材来源 | 文案策略 | 占比建议 |
|---------|---------|---------|---------|---------|
| 工厂实拍 | `factory_real` | 库中随机选 6-9 张（跨分类：生产线/喷涂线/打包） | 描述生产流程 + 工厂规模，套信任话术 | 30% |
| AI 效果图 | `ai_render` | 调用 AI 生图 API 生成 3-6 张 | 描述颜色/工艺/场景推荐 | 30% |
| 干货科普 | `knowledge` | 1 张封面图 + 自动生成对比表格图 | AI 生成科普长文，结构化排布 | 25% |
| 发货展示 | `shipping` | 库中随机选 3-6 张打包/装车图 | 简短文案，强调源头工厂 | 15% |

#### 2.3.2 生成流程

```
1. 选择内容类型（或按配比自动选）
2. 从素材库按类型标签选图（排除疲劳素材）
3. AI 调用 Prompt 模板生成文案
4. 拼接标题 + 正文 + 标签 + 配图 + 固定话术钩子
5. 输出为可发布的完整内容草稿
```

#### 2.3.3 固定话术钩子

每条生成内容的末尾自动追加（可配置）：

> 私信发图纸，源头工厂直接报价。主页有联系方式，没有中间商差价。

#### 2.3.4 生成模式

- **单条生成**：手动选择类型 → 生成（已有功能，不改变）
- **批量生成**：选择数量和类型配比 → 一键生成 N 条
- **定时自动生成**：配合排期，每天/每周定时生成指定数量的内容

#### 2.3.5 定时自动生成配置

在「设置」页新增区块：

- 每日生成数量（默认 1 条）
- 内容类型配比（可拖拽调整占比）
- 发布时间偏好（默认 12:00 / 18:00 / 21:00 三个时段随机）
- 开启/关闭自动生成开关

**实现方式**：前端定时器 + 手动触发，不做服务端 cron（本地工具，服务端不常驻）。用户打开工具时检查是否有待生成任务。

#### 2.3.6 验收标准

- [ ] 支持按内容类型从素材库自动选图
- [ ] 疲劳素材自动排除
- [ ] 每条生成内容的末尾自动追加固定话术
- [ ] 批量生成支持一次生成 N 条
- [ ] 自动生成配置页面可见且可修改
- [ ] 生成的内容自动保存到内容列表
- [ ] 生成的内容自动排期到日历

### 2.4 数据回收引擎升级（Metrics V2）

**对标已有**：`src/app/analytics/page.tsx`（保留手动录入，新增结构化和分析）

#### 2.4.1 按内容维度的数据录入

当前问题：MVP 的数据录入没有真正绑定到 Content —— 使用了 `contentId: "temp"` 占位符。

改为：
- 数据录入时选择已发布的内容（下拉列表）
- 每条 Metric 真实绑定到 Content
- 内容详情页显示该条内容的历史数据

#### 2.4.2 内容表现分析

新增分析维度：

- **按内容类型聚合**：`factory_real` vs `ai_render` vs `knowledge` vs `shipping` 的平均互动率对比
- **发布时间分析**：不同时段发布的平均互动率
- **关键词效果**：标记了不同标签的内容表现对比
- **Top 10 / Bottom 10**：表现最好和最差的内容排名

#### 2.4.3 数据看板

在 analytics 页面新增 Tab 切换：
- Tab 1：数据概览（已有的总览卡片 + 趋势图）
- Tab 2：内容排名（按互动率排序的表格，高亮标注 Top/Bottom）
- Tab 3：类型分析（按内容类型的柱状图对比）

#### 2.4.4 验收标准

- [ ] 数据录入绑定真实 Content ID
- [ ] 内容排名表显示 Top 10 和 Bottom 10
- [ ] 按内容类型的平均互动率对比图
- [ ] 内容详情页显示历史数据列表

### 2.5 策略迭代引擎（Strategy Engine）【全新模块】

#### 2.5.1 功能描述

基于回收的数据，系统自动给出优化建议，形成自我迭代闭环。

#### 2.5.2 策略分析维度

| 分析项 | 数据来源 | 策略动作 |
|--------|---------|---------|
| 内容类型效果排名 | 各类型平均互动率 | 调高高效类型占比，降低低效类型占比 |
| 选题热度趋势 | 标签关键词互动率 | 推荐热门选题方向 |
| 素材使用频率 | 素材 usageCount | 高使用频率素材参与度变化 → 判断是否审美疲劳 |
| 发布时间优化 | 不同时段互动率 | 推荐最佳发布时间 |
| 互动率阈值告警 | 连续 N 条互动率下降 | 触发内容策略复核提醒 |

#### 2.5.3 「策略建议」页面

新增侧栏菜单项「策略建议」。

页面内容：
- **内容配比建议**：当前配比 vs 建议配比，给出调整理由（数据支撑）
- **选题推荐**：基于高互动内容的标签分析，推荐 3-5 个新选题方向
- **素材刷新提醒**：哪些分类素材使用饱和/疲劳，建议补拍
- **发布时间建议**：最佳发布时间段

#### 2.5.4 自动化调整

策略建议中的「内容配比」可直接应用到自动生成引擎的配比配置中（一键应用）。

#### 2.5.5 验收标准

- [ ] 策略建议页显示内容类型效果排名
- [ ] 基于历史数据推荐新选题方向
- [ ] 素材疲劳/素材缺口提醒
- [ ] 配比建议可一键应用到自动生成配置

## 3. 数据库 Schema 变更

### 3.1 Asset 模型扩展（修改已有）

在已有 Asset 模型上增加字段：

```prisma
model Asset {
  id         String    @id @default(uuid())
  type       String    // 改为枚举值：production_line | spray_line | raw_material | finished_product | packing_shipping | detail_closeup | color_swatch | ai_render
  url        String
  title      String    @default("")
  tags       String    @default("")
  usageCount Int       @default(0)    // 新增
  lastUsedAt DateTime?                 // 新增
  isFatigued Boolean   @default(false) // 新增：手动标记疲劳
  createdAt  DateTime  @default(now())
}
```

### 3.2 MaterialTask 模型（新增）

```prisma
model MaterialTask {
  id            String    @id @default(uuid())
  title         String
  description   String    @default("")
  requiredTypes String    @default("")   // 逗号分隔的素材类型
  requiredCount Int       @default(5)
  status        String    @default("pending")  // pending | done
  dueDate       String?
  completedAt   DateTime?
  createdAt     DateTime  @default(now())
}
```

### 3.3 Content 模型扩展（修改已有）

```prisma
model Content {
  // ...已有字段...
  contentType  String    @default("knowledge")  // 新增：factory_real | ai_render | knowledge | shipping
  publishHook  String    @default("私信发图纸，源头工厂直接报价。主页有联系方式，没有中间商差价。")  // 新增：固定话术钩子
}
```

### 3.4 自动生成配置（新增）

不存数据库，存 localStorage（设置页面级别）：

```typescript
interface AutoGenConfig {
  enabled: boolean
  dailyCount: number          // 默认 1
  contentTypeRatios: {        // 内容类型配比（百分比，合计 100）
    factory_real: number      // 默认 30
    ai_render: number         // 默认 30
    knowledge: number         // 默认 25
    shipping: number          // 默认 15
  }
  preferredHours: number[]    // 默认 [12, 18, 21]
  fatigueThreshold: number    // 默认 3（素材使用 N 次后标记疲劳）
}
```

### 3.5 PromptTemplate 扩展

为 4 种内容类型各补充一个 Prompt 模板（已有的 3 个模板保留不变）：

| 模板 ID | 名称 | 内容类型 | 说明 |

| `auto-factory-real` | 工厂实拍类 | factory_real | 生产流程描述 + 工厂规模信任话术 |
| `auto-ai-render` | AI效果图类 | ai_render | 颜色推荐 + 工艺描述 + 场景应用 |
| `auto-knowledge` | 干货科普类 | knowledge | 对比表格 + 专业知识 + 避坑指南 |
| `auto-shipping` | 发货展示类 | shipping | 发货实况 + 源头工厂 + 排期提醒 |

## 6. 非功能需求

- **数据一致性**：素材 usageCount 在每次内容生成时原子更新
- **性能**：批量生成 5 条内容 ≤ 60 秒（取决于 AI API 响应）
- **离线**：本地工具，素材库图片存本地 public/uploads/，数据库 SQLite 本地文件
- **安全**：API Key 继续仅存 localStorage，不暴露到服务端日志
- **兼容**：保持 Chrome/Edge/Safari 最新版兼容

---

## 7. 边界情况

- **素材库为空时自动生成**：提示"素材库素材不足，请先上传素材"，跳转到拍摄任务页
- **AI API 调用失败**：单条失败不影响批量中其他条，失败条标记为「生成失败」，支持重试
- **所有素材疲劳**：提示"所有素材已标记疲劳，建议重置疲劳标记或上传新素材"
- **拍摄任务重复生成**：已有同类型未完成任务，不重复生成
- **数据不足时策略分析**：数据量 < 10 条时，策略页显示「数据积累中，暂无法分析」

## 8. 迭代优先级

### P0（第一阶段：人机协作支撑）
- 素材库 V2（分类 + 使用追踪 + 疲劳检测）
- 拍摄任务生成与列表
- 内容自动生成（单条 + 批量）
- 内容类型 + 固定话术

### P1（第二阶段：数据闭环）
- 数据回收引擎升级（绑定 Content + 排名 + 类型分析）
- 策略建议（内容配比 + 选题推荐）

### P2（第三阶段：完全自动化）
- 自动生成配置 + 定时触发
- 一键应用策略建议
- 素材覆盖率自动检测和任务自动派发

## 9. 成功标准

- [ ] 用户只需定期拍照入库，其余内容生产由系统完成
- [ ] 系统可根据素材覆盖率自动派发拍摄任务
- [ ] 数据回收后能给出可操作的内容策略建议
- [ ] 单个用户每天维护时间 < 10 分钟（拍照除外）
- [ ] AI 生成的内容用户满意度 > 50%（不需要大改就能发布）
