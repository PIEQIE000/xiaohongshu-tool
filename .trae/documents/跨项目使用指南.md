# Harness Engineering 实践框架 - 跨项目使用指南

## 一、在新项目中使用本框架

### 方法 1：直接复制框架文件（推荐）

#### 步骤 1：创建新项目目录

```bash
mkdir my-new-project
cd my-new-project
```

#### 步骤 2：复制框架文件

将以下文件和目录从原项目复制到新项目根目录：

```
需要复制的内容：
├── AGENTS.md                           ← 必须
├── EVOLUTION.md                        ← 必须
├── .trae/
│   └── skills/                         ← 必须（包含 5 个 Skill）
│       ├── product-spec-builder/
│       ├── design-brief-builder/
│       ├── dev-planner/
│       ├── dev-builder/
│       └── code-reviewer/
└── docs/
    ├── specs/                          ← 必须（空目录）
    ├── design/                         ← 必须（空目录）
    ├── plans/                          ← 必须（空目录）
    └── feedback/                       ← 必须（空目录）
        └── FEEDBACK-INDEX.md           ← 必须
```

#### 步骤 3：用 Trae Solo 打开新项目

1. 打开 Trae Solo
2. 选择「打开文件夹」，选择新项目目录
3. Trae Solo 会自动识别 `.trae/skills/` 下的所有 Skill

#### 步骤 4：开始使用

直接在对话框中输入产品想法，系统会自动匹配并触发对应的 Skill。

---

### 方法 2：使用 Git 克隆

如果框架已提交到 Git 仓库：

```bash
# 克隆框架作为起点
git clone https://your-repo/harness-framework.git my-new-project
cd my-new-project

# 删除示例内容，保留框架结构
rm -rf src/* package.json  # 删除示例项目文件（如果有）
```

---

### 方法 3：手动创建（从零开始）

如果不想复制文件，可以手动创建：

#### 1. 创建目录结构

```bash
mkdir -p .trae/skills docs/specs docs/design docs/plans docs/feedback
```

#### 2. 创建 AGENTS.md

在项目根目录创建 `AGENTS.md`，内容如下：

```markdown
# AGENTS.md - 项目 AI 操作手册

## 开发工作流
严格遵循以下流程，不可跳过任何阶段：
Product Spec → Design Brief → Dev Plan → Dev Build → Code Review

## 反模式防御
1. 禁止跳过 Spec 直接写代码
2. 禁止跳过 Design 直接写 UI
3. 禁止跳过 Plan 直接写代码
4. 禁止跳过 Review 直接提交
5. 禁止一次改多处
```

#### 3. 创建 Skill 文件

在 `.trae/skills/` 下创建对应的 Skill 文件夹，每个文件夹放入 `SKILL.md` 文件。

你可以直接复制现有项目的 SKILL.md 内容。

## 二、完整使用流程

### 场景：从零开发一个"待办事项管理应用"

#### 第 1 步：打开项目，描述需求

在 Trae Solo 对话框中输入：

```
我想做一个待办事项管理应用，支持创建、编辑、删除任务，可以按标签分类。
```

**自动触发**：product-spec-builder

**AI 会做的事**：
1. 追问关键细节（一次一问）
2. 提供实现方案供选择
3. 生成 Product Spec 文档

**你会看到的**：

```
AI: 好的！让我先理解一下你的需求。这个待办应用主要解决什么问题？
    是个人使用，还是团队协作？

你: 个人使用为主，但以后可能想分享给家人

AI: 明白了。那最核心的功能有哪些？除了创建/编辑/删除任务和标签分类，
    还需要优先级设置、截止日期提醒等功能吗？

你: 优先级设置需要，提醒功能暂时不需要

[继续追问...]

AI: 我整理了 2 种方案供你选择：
    方案 A: 纯前端单页应用（LocalStorage 存储）
    方案 B: 全栈应用（前端 + 后端 API + 数据库）
    
    我推荐方案 A 作为 MVP，开发快且满足当前需求。你选哪个？

你: 方案 A

AI: 好的，已生成 Product Spec，保存到 docs/specs/2026-05-19-todo-app-spec.md
    请确认内容是否符合预期。确认后我们进入设计阶段。
```

#### 第 2 步：定义视觉风格

当 Spec 确认后，输入：

```
深色主题，极简风格，类似 Notion 的感觉
```

**自动触发**：design-brief-builder

**AI 会做的事**：
1. 追问配色、字体、组件风格
2. 生成 Design Brief 文档

#### 第 3 步：制定开发计划

当 Design Brief 确认后，输入：

```
Spec 和设计都确认了，制定开发计划
```

**自动触发**：dev-planner

**AI 会做的事**：
1. 读取 Spec 和 Design Brief
2. 技术调研（查找可用的前端组件库）
3. 拆分 Phase 和 Task
4. 生成 Dev Plan 文档

**你会看到类似**：

```
## Phase 1: 基础架构
**交付物**：项目初始化，可运行的空壳应用

| ID   | 描述               | 验收标准        | 依赖 | Wave |
|------|-------------------|----------------|------|------|
| T001 | 初始化 React 项目   | npm run dev 可运行 | 无   | 1    |
| T002 | 配置 Tailwind CSS  | 样式正常渲染      | T001 | 2    |

## Phase 2: 核心功能 - 任务 CRUD
**交付物**：可创建、编辑、删除任务

| ID   | 描述               | 验收标准        | 依赖 | Wave |
|------|-------------------|----------------|------|------|
| T003 | 创建任务组件        | 点击按钮可添加任务  | T002 | 1    |
| T004 | 任务列表组件        | 显示所有任务列表    | T003 | 2    |
...
```

#### 第 4 步：开始开发

确认计划后，输入：

```
计划没问题，开始开发
```

**自动触发**：dev-builder

**AI 会做的事**：
1. 从 T001 开始逐 Task 实现
2. 每个 Task 遵循 TDD（先写测试 → 实现 → 重构）
3. 每个 Task 完成后编译验证
4. 自动标记完成，进入下一个 Task

**你会看到类似**：

```
正在执行 T001: 初始化 React 项目
1. 创建测试文件 tests/init.test.ts...
2. 编写测试...
3. 运行测试 → 失败 ✅（符合预期）
4. 创建项目文件...
5. 运行测试 → 通过 ✅
6. 运行构建 → 无错误 ✅
7. T001 完成！

正在执行 T002: 配置 Tailwind CSS...
```

#### 第 5 步：代码审查

每个 Phase 或 Task 完成后，输入：

```
审查一下代码
```

**自动触发**：code-reviewer

**AI 会做的事**：
1. Stage 1：对照 Spec 检查功能完整性
2. Stage 2：五轴评审代码质量
3. 输出审查报告

## 四、跨 Session 继续开发

### 场景：昨天开发到一半，今天继续

**输入**：
```
继续开发。请先重新读取 Product Spec 和 Dev Plan，然后从 T008 开始。
```

**为什么需要"重新读取"**？
AI 的上下文窗口有限，新 Session 中没有之前的记忆。重新读取文档确保 AI 基于完整上下文继续工作。

## 五、框架自定义

### 修改 Skill 行为

编辑 `.trae/skills/[skill-name]/SKILL.md` 文件，修改：
- `description`：改变触发条件
- 执行流程：调整步骤
- 模板：自定义输出格式

### 新增 Skill

1. 在 `.trae/skills/` 下创建新文件夹（小写连字符命名）
2. 创建 `SKILL.md` 文件
3. 定义 YAML 元数据和执行流程

示例：

```
.trae/skills/
└── bug-fixer/
    └── SKILL.md          ← 新增的调试 Skill
```

### 修改反模式防御

编辑 `AGENTS.md`，在"反模式防御"部分添加新的禁止行为。

---

## 六、注意事项

1. **每个新项目都需要复制完整的框架文件**，缺一不可
2. **Skill 文件是 AI 看的，不是人看的**，不要随意修改格式
3. **AGENTS.md 是总控文件**，修改时注意不要破坏工作流约束
4. **定期查看 EVOLUTION.md**，确认是否有需要批准的进化规则
5. **不要一次性让 AI 做太多**，按 Phase 逐步推进
